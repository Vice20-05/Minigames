1. WHAT IS THIS?
---------------------------------------------------------------------
A small but WORKING game made with Java Swing (the built-in Java
library for windows and drawing). Right now you can:

  - press W to start (the game waits until then)
  - drive the F1 car on a 2-lane road
  - speed up, brake, and steer freely left/right (analog-style: the
    longer you hold A or D, the harder you turn)
  - see the road scroll faster the faster you drive
  - dodge traffic cars (random pictures) that spawn in random lanes
  - after 500 points, some traffic cars switch lanes
  - get points over time (more points when you go faster)
  - get a NEAR MISS bonus when you pass very close to a car
  - crash, see your score + near misses, and press R to restart

The player car, the traffic and the background already use pictures
(see section 9). If a picture is missing, the game draws a colored
box instead, so it never crashes because of art.

2. HOW TO RUN THE GAME
---------------------------------------------------------------------
The class with the main() method is:   GameWindow.java

All the files start with the line:     package f1_game.base;
That means Java expects them inside the folder  src/f1_game/base/
and that  "src"  is the SOURCE ROOT (the top folder of the code).

--- Option A: IntelliJ IDEA (easiest) ---
  1. File -> Open -> choose the "Minigames" folder.
  2. Right-click the "src" folder -> Mark Directory as -> Sources Root
     (it turns blue). Skip this if it is already blue.
  3. Open src/f1_game/base/GameWindow.java
  4. Click the green play button next to "public static void main".

--- Option B: VS Code ---
  1. Install the "Extension Pack for Java".
  2. Open the "Minigames" folder.
  3. Open GameWindow.java and click "Run" above the main method.

--- Option C: Command line (terminal) ---
  Go into the Minigames folder (the one that contains "src"), then:

     javac -d out src/f1_game/base/*.java
     java -cp out f1_game.base.GameWindow

  Line 1 compiles (javac = Java compiler). "-d out" puts the compiled
         .class files into a folder called "out".
  Line 2 runs it. "-cp out" says "look for classes in out".
  (The "out" folder is in .gitignore, so it won't be pushed to GitHub.)

You need Java 17 or newer (we use the new "switch with ->" style).

  S  or  Down arrow    brake

4. THE FILES (what each class does)
---------------------------------------------------------------------
All in  src/f1_game/base/

  GameWindow.java     The window (JFrame). Has main(). START HERE.
        |
        v
  GamePanel.java      The heart: the game loop, updating and drawing.
        |             It owns all the objects below.
        |
        +-- KeyHandler.java      Remembers which keys are held down.
        +-- Road.java            Draws grass, asphalt, scrolling lines.
        +-- PlayerCar.java       Your car (speed + steering).
        +-- TrafficCar.java      One traffic car (its lane, speed, picture,
        |                        near-miss flag, sliding to a new lane).
        +-- TrafficSpawner.java  Decides when/where new traffic appears,
                                 picks a random picture for it, and makes
                                 cars change lanes after 500 points.

  GameObject.java     The PARENT class of PlayerCar and TrafficCar.
                      Holds position, size, color, image, and draws it.
                      (PlayerCar "extends" GameObject = inheritance)

  GameConfig.java     All the numbers (window size, speeds, lanes...)
                      in one place.

  ImageLoader.java    Loads pictures from the Resorces folder.
                      load(path) = one picture,
                      loadFolder(path) = EVERY .png inside a folder.

The rule we follow: ONE class = ONE job. If something is wrong with
the lane lines, you know to look in Road.java. If the car brakes too
slowly, you look in GameConfig.java (BRAKE_POWER).


---------------------------------------------------------------------
5. HOW THE GAME LOOP WORKS (the most important part!)
---------------------------------------------------------------------
A game is like a flip-book. 60 times every second we:

      +-----------------------------------------------+
      |  Timer "ticks" (every ~16 ms)                 |
      |        |                                      |
      |        v                                      |
      |  actionPerformed()                            |
      |        |                                      |
      |        +--> updateGame()   1) MOVE everything |
      |        |                                      |
      |        +--> repaint()      2) DRAW everything |
      |                 |          (Swing then calls  |
      |                 |           paintComponent)   |
      |                 v                             |
      |  wait for the next tick and do it again...    |
      +-----------------------------------------------+

What happens in updateGame() (GamePanel.java), in this order:
  0. two "gates" at the top:
       - game over?       -> only wait for R, nothing else moves
       - not started yet? -> wait for W, nothing else moves
  1. player.update(keys)            read the keyboard, change speed, steer
  2. road.update(...)               move the lane lines (scrolling)
  3. spawner.update(...)            maybe add a new traffic car
  4. spawner.updateLaneChanges(...) after 500 points: maybe a car switches lane
  5. car.update(...)                move every traffic car (down/up AND sideways)
  6. removeIf(isOffScreen)          delete cars that left the screen
  7. checkCollisions()              crash? -> game over. Near miss? -> bonus
  8. updateScore()                  add points
  9. count down the "NEAR MISS!" text

What happens in paintComponent() - ORDER MATTERS, like painting on a
real canvas: whatever you paint LAST ends up ON TOP.
  1. background + road  (back)
  2. traffic cars
  3. player car
  4. "NEAR MISS! +50" text (only right after a near miss)
  5. HUD text            (speed, score, multiplier, time)
  6. "Press W to start"  (only before the game started)
  7. game over screen    (only if you crashed, front)

Golden rule: update() only CHANGES numbers, draw() only PAINTS them.
Don't move things inside draw(), and don't draw inside update().

6. THE COORDINATE SYSTEM (where is x / y?)
---------------------------------------------------------------------
In Swing, (0, 0) is the TOP-LEFT corner, and y goes DOWN.
(It is the other way around from maths class!)

     (0,0) ------------------------> x  (480)
       |
       |        +----+   <- (x, y) of an object is ITS top-left corner
       |        |car |
       |        +----+
       |
       v
       y (720)

So:  y gets BIGGER  -> the object moves DOWN the screen
     y gets SMALLER -> the object moves UP
     a negative y   -> the object is above the screen (hidden)

That's why new traffic starts at y = -CAR_HEIGHT: it begins just
above the top edge, so it "drives into" the screen.

Lanes are numbered from the left: 0, 1 (LANE_COUNT = 2).
Road.laneCenterX(lane) tells you the x of the middle of a lane.
The PLAYER is not locked to a lane anymore (free steering), but the
TRAFFIC still drives in lanes.


---------------------------------------------------------------------
7. HOW SCROLLING AND SPEED WORK
---------------------------------------------------------------------
The player car NEVER moves up the screen. Its y stays the same.
The trick: the WORLD moves down instead.

  - Lane lines move down by:   playerSpeed * PIXELS_PER_KMH
    Example: 200 km/h * 0.08 = 16 pixels every frame.

  - Traffic cars move by the DIFFERENCE in speed:
        (playerSpeed - trafficSpeed) * PIXELS_PER_KMH
    You at 200, them at 80  -> +9.6 px -> they come DOWN towards you.
    You at 50,  them at 80  -> -2.4 px -> they drive UP and away.

  - Score you see = baseScore * multiplier
    baseScore grows by POINTS_PER_SECOND every second (+ near-miss bonuses)
    multiplier = 1 + speed / 200, but never more than MAX_MULTIPLIER
       0 km/h -> x1.0      100 km/h -> x1.5      200 km/h -> x2.0
    The multiplier is "live": brake and the score on screen goes down,
    speed up and it goes up again.

  - Steering works like speed, but sideways ("analog stick" feel):
    holding A/D adds STEER_ACCELERATION to the sideways speed every frame
    (up to MAX_STEER_SPEED). Let go and it shrinks by STEER_RETURN until
    the car goes straight again. The car can't leave the asphalt.

  - Near miss: PlayerCar.getNearMissBounds() is a box NEAR_MISS_MARGIN
    pixels bigger than your car on every side. A traffic car touching
    that box (but not your car) = near miss = +NEAR_MISS_BONUS.
    Each car has a "nearMissed" flag so it only pays ONCE, otherwise
    you would get the bonus every frame it stays close.

  - Lane changes: from LANE_CHANGE_SCORE points on, every frame each car
    has a LANE_CHANGE_CHANCE to switch to the lane next to it. Only if:
    it never switched before, it is on screen and still well in front
    of you, and the other lane is free near it. It then slides over at
    LANE_CHANGE_SPEED pixels per frame (not a jump, so you can react).
    This is what stops you from just sitting between the lanes.

8. HOW TO CHANGE THINGS (settings)
---------------------------------------------------------------------
Open GameConfig.java. Change a number, run the game again. Try:

  MAX_SPEED          = 400     -> higher top speed
  ACCELERATION       = 2.0     -> faster acceleration
  LANE_COUNT         = 3       -> 3 lanes
  SPAWN_EVERY_TICKS  = 15      -> MUCH more traffic
  PIXELS_PER_KMH     = 0.12    -> the game feels faster

  STEER_ACCELERATION = 0.3     -> steering builds up slower (smoother)
  STEER_RETURN       = 0.3     -> car keeps drifting longer ("ice")
  MAX_STEER_SPEED    = 9       -> much quicker sideways

  NEAR_MISS_MARGIN   = 30      -> near misses are easier to get
                                  (careful: too big and sitting between
                                  the lanes gives near misses again)
  NEAR_MISS_BONUS    = 100     -> near misses are worth more
  LANE_CHANGE_SCORE  = 0       -> cars change lanes from the start
  LANE_CHANGE_CHANCE = 0.03    -> cars change lanes a LOT more
  LANE_CHANGE_SPEED  = 4       -> lane changes are faster (harder)

Changing numbers and watching what happens is the BEST way to learn
how the code works. You can always change it back.

9. PICTURES (ART)
---------------------------------------------------------------------
Where the pictures are:
  Resorces/Textures/f1_game_playerCar/f1.png        the player car
  Resorces/Textures/f1game_grass_background/        grass + road
  Resorces/Textures/traffic/                        ALL traffic cars

Use PNG with a transparent background, and draw cars facing UP.

--- Adding a new TRAFFIC car (no code needed!) ---
  Just put another .png into  Resorces/Textures/traffic/
  TrafficSpawner loads EVERY .png in that folder once at the start
  (ImageLoader.loadFolder) and gives each new car a random one.
  The name doesn't matter. 6 pictures now, 20 later: it just works.

  Traffic cars keep the SHAPE of their picture: every car is
  CAR_HEIGHT (90) tall, and the width comes from the picture.
  So a thin motorbike (44 x 100) gets a thin box (39 px) and its
  hitbox fits. Best results with pictures around 70 x 131.

--- Changing the PLAYER car ---
  In PlayerCar.java, in the super(...) call of the constructor,
  change the path "Resorces/Textures/f1_game_playerCar/f1.png".
  The player picture is stretched to CAR_WIDTH x CAR_HEIGHT (50 x 90).

If the file can't be found, the game does NOT crash: it prints
"Could not load image: ..." in the console and keeps the colored box.
Note: the path is relative to the folder you RUN the game from
(the Minigames folder).

10. NEXT STEPS - WHAT YOU CAN ADD (with hints)
---------------------------------------------------------------------
These are all from minigames-plan.md. Do them one at a time, and run
the game after every small change. Easiest first.

[x] DONE: press W to start, traffic pictures from a folder, analog
    steering, near-miss bonus + "NEAR MISS!" text, lane changes after
    500 points. (How they work: see section 7.)

[ ] 1. BLINKERS BEFORE A LANE CHANGE
    Right now a car starts sliding with no warning. Make it fairer:
    in TrafficCar, when changeLane() is called, first count down a
    "blinkTicks" (e.g. 40 frames) before the car actually moves, and in
    draw() paint a small orange square on that side while it blinks.
    Hint: (blinkTicks / 8) % 2 == 0  -> on/off flashing.

[ ] 2. OVERTAKE BONUS
    A car is overtaken when it goes from ABOVE the player to BELOW the
    player. Hint: in TrafficCar add a boolean "overtaken". In GamePanel,
    if car.getY() > player.getY() + CAR_HEIGHT and not overtaken yet
    -> add points and mark it.

[ ] 3. HIGH SCORE ON THE GAME OVER SCREEN
    Add  private double bestScore;  in GamePanel. When you crash:
    if (score > bestScore) bestScore = score;  then draw it.
    (Later this goes into the database!)

[ ] 4. DIFFICULTY PHASES (traffic gets denser every ~30 s)
    We already count frames in "ticks". Seconds = ticks / GameConfig.FPS.
    Hint: give TrafficSpawner an update(traffic, seconds) parameter and
    make the spawn delay smaller as time goes on, e.g.
        int delay = 45 - (seconds / 30) * 5;
        if (delay < 15) delay = 15;     // the CAP from the plan
    The "never block all lanes" rule is already there.

[ ] 5. ROADBLOCKS / POTHOLES after ~2 minutes
    Make a new class  Obstacle extends GameObject  (copy TrafficCar as
    a start). Obstacles don't drive, so their speed is 0:
        y += playerSpeed * PIXELS_PER_KMH;
    Keep a  List<Obstacle>  in GamePanel and treat it like traffic.

[ ] 6. A PAUSE BUTTON (P)
    Add VK_P to KeyHandler, add  boolean paused  to GamePanel, and at
    the start of updateGame():  if (paused) return;
    (Careful: if you just check "P is held", holding P for 1 second
    would switch pause on/off 60 times. Remember if P was already held
    last frame, and only react on the FIRST frame it goes down.)

[ ] 7. CONNECT TO THE MAIN MENU
    From src/Main.java (or f1Main.java) you can start the game with:
        new f1_game.base.GameWindow();
    Note: f1Main.java has no "package" line yet. When we build the
    menu, we should give it  package f1_game;  so it matches its folder.
    (GameWindow already uses DISPOSE_ON_CLOSE, so closing the game will
    not close the whole menu.)

11. COMMON ERRORS AND HOW TO FIX THEM
---------------------------------------------------------------------
"The keys don't do anything!"
   -> Click inside the game window once. The panel needs FOCUS to get
      key presses. (GamePanel calls requestFocusInWindow() for this.)

"error: cannot find symbol"
   -> A typo, or you used a class/variable that doesn't exist. Java is
      CASE SENSITIVE: speed and Speed are different things.

"Could not find or load main class"
   -> Run it from the Minigames folder, and use the FULL name with the
      package:  java -cp out f1_game.base.GameWindow

"package f1_game.base does not exist" / red package line in IntelliJ
   -> "src" is not marked as Sources Root (see section 2, option A).

The car steers way too fast / too slow / feels like ice
   -> Tune STEER_ACCELERATION, MAX_STEER_SPEED and STEER_RETURN in
      GameConfig.java (see section 8).

I get the near-miss bonus many times for ONE car
   -> The car isn't marked. After adding the bonus you must call
      car.markNearMissed(), and the if must check !car.hasNearMissed().

"Could not find image folder: Resorces/Textures/traffic"
   -> The folder was moved or renamed (note: "Resorces", not
      "Resources"). Traffic falls back to colored boxes until fixed.

Things flicker
   -> Only draw inside paintComponent(), never somewhere else.

12. SMALL JAVA GLOSSARY
---------------------------------------------------------------------
class        A blueprint. "PlayerCar" describes what every player car is.
object       A real thing made from the blueprint:  new PlayerCar()
extends      Inheritance: "PlayerCar extends GameObject" = a PlayerCar IS
             a GameObject, and gets all its variables and methods.
super(...)   Calls the constructor of the parent class.
@Override    "I'm replacing a method that the parent already has."
private      Only THIS class can use it.
protected    This class AND its children can use it.
public       Everybody can use it.
static       Belongs to the class, not to one object (GameConfig.FPS).
final        Can't be changed after it is set.
List<T>      A list that can grow/shrink:  ArrayList<TrafficCar>
JFrame       A window.
JPanel       A rectangle inside a window that you can draw on.
Graphics2D   The "pen" you draw with:  g.setColor(...), g.fillRect(...)
Timer        Calls a method again and again (our game loop).
Rectangle    A box. box1.intersects(box2) = do they overlap? (collision)

Good luck, and have fun with it!
